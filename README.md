I like the part of software that sits underneath the reassuring architecture diagram — the memory, the protocols, the failure modes, and the 2 a.m. decisions that quietly get promoted to "design" once enough things depend on them.

Everything below is measured, rebuilt every morning by a workflow in this repo, and not rounded in my favour. Some of it is a Game Boy. I did not have a good reason.

## Codeforces, but it is Tetris

<div align="center">

<picture>
  <source media="(max-width: 600px)" srcset="https://raw.githubusercontent.com/jiteeshghodke456-del/jiteeshghodke456-del/output/tetris-mobile.svg?v=9" />
  <img width="100%" src="https://raw.githubusercontent.com/jiteeshghodke456-del/jiteeshghodke456-del/output/tetris.svg?v=9" alt="Codeforces submissions stacked as a Game Boy Tetris board, one column per problem" />
</picture>

</div>

Ten columns, because a Game Boy well is ten columns. One block per submission, stacked in the order I sent them. Green means the judge accepted it. Violet means the judge disagreed, and the shade tells you how creatively.

These are the ten problems that took the most attempts, rather than the ten most recent, on the grounds that the recent ones went in quietly and make for a very boring picture. The tallest column is problem 158A. It took thirteen attempts. Eleven of them were wrong answers. I remember it fondly, in the way you remember an illness.

The bottom row is full because every problem on the board was attempted at least once, which is the lowest bar in competitive programming and the only line I clear reliably.

## The snake that eats my consistency

<div align="center">

<picture>
  <source media="(max-width: 600px)" srcset="https://raw.githubusercontent.com/jiteeshghodke456-del/jiteeshghodke456-del/output/snake-mobile.svg?v=9" />
  <img width="100%" src="https://raw.githubusercontent.com/jiteeshghodke456-del/jiteeshghodke456-del/output/snake.svg?v=9" alt="Nokia Snake eating a year of GitHub contributions" />
</picture>

</div>

It grows one segment for every contribution day it eats. There are thirty of them, so it finishes rather quickly and then has to sit there.

It plans its route along a Hamiltonian cycle and only takes a shortcut when the shortcut provably cannot trap it, which is a great deal more forethought than went into most of the commits it is eating.
